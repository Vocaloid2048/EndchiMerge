# 物理參數

> **狀態**：暫定。本文件記錄 `public/config/levels.json` 現行數字的**推導規則**，
> 以及它們為何還不能當真。設計層的定案見 `design.md` §2.4、§4.3。

## 座標系

```
VIRTUAL_HEIGHT = 1000                      // 鎖定的虛擬高度（core/constants.ts）
scale          = containerHeightPx / 1000  // 只用於畫面投影
VIRTUAL_WIDTH  = containerWidthPx / scale  // 隨容器浮動
```

半徑以**虛擬單位**定義，因此相對比例在所有裝置一致。重力與密度等物理常數同樣
以虛擬單位定義，`scale` 不參與物理計算——否則視窗一變，手感就會跟著變。

設計稿的容器約為 15:16（略高於寬），對應 `VIRTUAL_WIDTH ≈ 937.5`。

## 暫定數字的來源

以下規則全部是**為了讓配置檔可運作而暫擬的**，不是平衡結論。

| 欄位 | 規則 | 現值 |
| --- | --- | --- |
| `radius` | 等比數列，公比 1.28，Lv1 = 13.5 | 13.5 → 124.5 |
| `density` | 全部相同 | 0.0010 |
| `restitution` | 線性遞減，由 0.20 降至 0.06 | 0.20 → 0.06 |
| `friction` | 全部相同 | 0.30 |
| `frictionAir` | 全部相同 | 0.005 |
| `score` | 2 的冪次，Lv1 固定為 0（永不經合成產生） | 0, 1, 2, 4 … 256 |
| `spawnWeight` | 只有前三級可掉落 | 70 / 25 / 5 |

**為何密度統一而非遞增**：密度統一意味質量 ∝ 面積 ∝ r²，這是物理上最自然的
預設。舊版規劃曾讓密度隨等級遞增，那會令 Lv10 的質量再乘上一個額外係數，
質量比從 85× 膨脹到數百倍，求解器在堆疊時容易抖動。先用自然值，真要調再調。

**目前的質量比**：Lv10 對 Lv1 為 `(124.5 / 13.5)² ≈ 85×`。這個數字要在校準時
親自感受——太大會導致小球被壓穿，太小則大球推不動小球。

**為何 Lv1 的 `score` 是 0**：`score` 定義為「由合成產生時獲得的分數」。
Lv1 只能靠掉落產生，永遠不會是合成的結果，所以 0。實際得分由 Lv2 起算。

## 碰撞形狀一律為圓

理由見 `design.md` §4.3，此處只記結論：輪廓多為凹多邊形，需凸分解，穩定性差；
物理與畫面即使有微小落差，玩家幾乎無感，但物理不穩會直接毀掉手感。視覺對齊由
「縮放 + 質心偏移」處理，**不改碰撞形狀**。

## 還沒定案的部分

| 項目 | 卡在哪 |
| --- | --- |
| 半徑取內切圓或外接圓 | 需 M0 校準原型目視挑選（`design.md` §9 Q9） |
| 上述整表的實際平衡值 | 同上，校準後整表重算 |
| 重力大小 | 尚未定，需與 `floatForceY` 同量級比較 |
| 容器寬高比夾制範圍 | 暫用 0.62–1.45，需原型驗證（Q11） |
| 溢出規則 | `overflowPenalty`、`spawnBlockEnabled` 的實際行為未定 |

## 改動這份配置時的注意事項

1. `radius` 與 `spawnWeight` 高度耦合。改半徑而不改權重，難度曲線會靜默走樣。
2. `mergeResult` 形成單鏈，最後一級必須是 `null`。斷鏈會讓合成靜默失敗。
3. 新增等級時，`sprite` 檔名必須與 `public/assets/sprites/` 完全一致（含中文）。
4. 半徑不得使 `2 × radius > VIRTUAL_WIDTH`，否則該等級一出現就會卡在兩牆之間。
